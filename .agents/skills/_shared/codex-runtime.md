# Codex desktop execution

The domain rules in these skills survive the Claude Code migration. Use this adapter for tool execution; historical workflow notes are evidence, not proof that a tool or hook is installed.

- **Skills:** project entrypoints live under `.agents/skills/`. Invoke by name (or `$skill-name`); old `/skill-name` wording is a user request, not a guaranteed slash command. Read referenced files from the skill's directory. Before using a missing asset, check `git ls-files` and the sparse checkout; selectively restore required inputs. Never manufacture an identity anchor or replace an approved asset.
- **Shell:** use the available terminal tool and the current shell. On Windows use PowerShell, `npm.cmd`, and `npx.cmd`; translate Bash line continuations and environment assignment. Do not run a Bash example literally in PowerShell. Prefer existing repository tools. Never read or print secrets; processes may receive required environment variables without displaying their values.
- **Browser:** use available browser tools and their supplied documentation (CUA in Codex desktop, or configured Playwright MCP). Never invent tool names. For repeatable tests use `npm.cmd run test:e2e` with the relevant test. Keep the requested viewport/screenshots. No available browser or missing login means that visual/account check is pending, not passed. Load `director-smoke` before entering the Director wizard.
- **Subagents:** use the available Codex collaboration tool with `code-executor`, `smoke-tester`, `explorer`, or `default` as appropriate. Supply scope, acceptance criteria, evidence and output paths; omit model overrides unless explicitly requested. If a required independent critic is unavailable, report independent review pending. Do not label self-review as independent review.
- **Images:** load the installed `imagegen` skill and use the native image generation/editing tool when available. Keep all identity anchors and exact approved inputs. The `codex-image` CLI wrapper is an optional local fallback, not a prerequisite for desktop generation. Never infer plan pricing or quota from a historical skill note.
- **Artifacts:** create self-contained local HTML using the existing builder/gates, link the absolute file path, and open it in Codex with the available file/browser panel tool. No Claude Artifact API, `callTool`, or `watchTool` is provided by these HTML files. Live data requires an explicitly available, authenticated integration; otherwise label a dated read-only snapshot. Publish only when explicitly requested using a supported hosting tool. Mobile browser verification still applies.
- **Goals and review:** keep the success/failure/verification contract in the conversation and project notes. Create a native goal only when the user explicitly requests a goal and the tool is available. Historical `/goal` and `/code-review` language does not install those commands; use the available goal/review or collaboration tools. Build/test and independent review gates remain required.
- **Boundaries:** paid AI/render tests require the approved purpose, pass/fail criteria, exact assets, evidence and maximum cost in `AGENTS.md`. Paid Veo also requires the nearby spec, passing preflight and approved `maxPaidRolls`. Never autonomously mutate ads, publish, deploy, send externally, or change production data. Check the actual project hook configuration before claiming automatic enforcement; prose obligations apply even when a hook cannot intercept an action.

Configuration references checked for this migration: [official skills documentation](https://learn.chatgpt.com/docs/build-skills) and [official subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents). Account, browser, image and paid media availability require a hands-on session check.
