## Layout

- `raw/` — as generated by ElevenLabs (kept so QA can re-run without re-paying)
- `bank/<class>/` — QA survivors: decoded transient lands ≤10ms from t=0
  (auto-trimmed where needed, re-verified after trim)
- `audition/` — **the files Neil listens to**: each class's variants at
  t = 1s, 3s, 5s… over the real music bed at render-ish levels (bed 0.25,
  SFX 0.9). Tonal classes (ding, sparkle, notification, chaching) get BOTH
  beds — mrbeast AND testimonial — per the music-bed-clash constraint.
- `qa-report.json` — per-sample onset measurements + verdicts
- `session-state.json` — generation spend counter (never re-spends on a file
  that exists in `raw/`)

## Ear-test procedure (Neil)

1. Play each `audition/<class>-audition-mrbeast.mp3`. Variants land at
   1s, 3s, 5s, … in ascending variant order **among survivors** (e.g. snap's
   first slot is v3 because v1/v2 were rejected — see `qa-report.json`).
2. For tonal classes, also play the `-testimonial` mix — a ding that works
   over hype music can clash with the soft piano bed.
3. Verdict per class: which variants are IN, which are OUT (e.g.
   "chaching: v1 v3 v5 in, rest out"). ≥4 survivors per class is the target
   for fingerprint-safe rotation; classes below 4 get a re-roll round.
4. Verdicts are recorded in the session log in sfx_upgrade_plan.md; approved
   sets move to the product bank in Slice 1.
